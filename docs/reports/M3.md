# M3 Implementation Report — Tracking

- Milestone: M3 — Tracking
- Date: 2026-08-01
- Status: **Implementation drafted; verification deferred by owner**

## Scope delivered

- An immutable `FaceTracker` protocol and `GeometricFaceTracker` implementation.
- Process-local, monotonically allocated temporary integer IDs that are never reused within a tracker instance.
- Deterministic geometric association using predicted centroid motion and IoU.
- Explicit track lifecycle: tracking, lost, and expiry after a configured bounded frame gap.
- Bounded metadata-only retention per track: frame sequence, capture timestamp, box, and confidence.
- Strict single-source and increasing-sequence checks.
- Strict, immutable tracking configuration and a `create_tracker()` factory that returns no tracker unless explicitly enabled.

## Explicit exclusions

M3 does **not** add face quality scoring, alignment, image/crop retention, embeddings, re-identification, profile matching, candidate enrollment, persistence, APIs, or settings changes. It stores no frame pixels, landmarks, embeddings, or identity data.

## Configuration

`tracking` is disabled by default and bounds all retained metadata:

- `max_missing_frames`
- `min_iou`
- `max_center_distance`
- `max_samples_per_track`
- `max_tracks`

## Commands executed

- A Claude Code, read-only, low-effort architecture review of M2 boundaries and the intended M3 scope was run before implementation.
- Automated tests, formatter/linter/type-checker runs, package checks, and hardware tests were **not run**, per the owner's request to skip tests for now.

## Verification status and limitations

No test counts, passing quality gates, or production-readiness claims are made. Geometric association is a best-effort continuity mechanism, not identity evidence; dense crossings, long occlusions, erratic detection ordering, and detector dropouts need the deferred deterministic scenario tests before M3 can be marked complete.
