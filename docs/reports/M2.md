## Scope Delivered

- Immutable, profile-independent `Point`, `BoundingBox`, `FaceLandmarks`, and `FaceDetection` contracts.
- A replaceable `FaceDetector` protocol and deterministic `MockFaceDetector`.
- An OpenCV `FaceDetectorYN`/YuNet adapter for zero, one, or multiple faces.
- Documented five-point landmark mapping, confidence filtering, frame clipping, and deterministic result ordering.
- Fail-closed validation of backend shape, dtype, finite values, confidence, box size, frame intersection, and configured output cardinality.
- Controlled error translation that omits backend details and configured model paths.
- Strict detector configuration with disabled/mock defaults and source-specific controls.
- SHA-256 verification of the exact in-memory model bytes passed to OpenCV, eliminating a check/load pathname race.
- Explicit debug overlays on copied frames, persisted only through the M1 owner-only/no-follow writer.
- A one-frame `face-profile detect` CLI command with count-only structured output.

No tracking, temporary track IDs, quality scoring, alignment, embeddings, identity recognition, enrollment, persistence, API, active-user selection, or host-setting mutation is included.

## Model Boundary

M2 does not bundle or select a detector model as a production default. This preserves ADR 0002's M5 provenance, intended-use, compatibility, and evaluation gate. Tests inject YuNet-compatible output rows over the existing generated geometric frame fixture, so zero/one/multiple contract behavior is deterministic and contains no person or biometric media.

A local interoperability smoke test used OpenCV Zoo's `face_detection_yunet_2023mar.onnx` from <https://github.com/opencv/opencv_zoo/raw/main/models/face_detection_yunet/face_detection_yunet_2023mar.onnx>:

- Size: 232,589 bytes
- SHA-256: `8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4`
- Upstream model source license: BSD 3-Clause
- Input: committed non-biometric `tests/fixtures/camera/synthetic.png`
- Result: successful backend load and zero detections

This smoke test proves adapter interoperability only. It is not detector-accuracy or production-rights evidence.

## Deterministic Detection Verification

Automated tests verify:

- Zero, one, and multiple-face outputs.
- Deterministic confidence and position ordering.
- Confidence filtering and per-frame input-size updates.
- The documented YuNet right-eye, left-eye, nose, right-mouth, left-mouth row mapping.
- Invalid shape, non-finite values, invalid confidence, and non-positive box rejection.
- Complex-valued rows, unsuccessful native status, and non-intersecting low-confidence rows are rejected fail closed.
- Backend row cardinality is bounded by the configured `top_k` value.
- Safe backend and output-conversion error translation.
- Native OpenCV model-load logging is silenced only during backend creation and its previous level is restored.
- Debug overlay copy semantics, landmarks, confidence, and safe render failures.
- Disabled and mock-backed factory behavior.
- Model checksum rejection before backend load, exact-byte loading under pathname replacement, and verified-model backend creation.
- Strict detector configuration and controlled invalid configuration.
- One-frame CLI acquisition, zero-result completion, and private debug output.

## Security and Privacy

- Camera and detection remain disabled in the shipped configuration.
- The disabled detector default is mock-backed and cannot load a model.
- YuNet-specific model and tuning fields are rejected for the mock backend.
- Real YuNet configuration requires an explicit local path and exact lowercase SHA-256.
- Factory, inference, output-conversion, and debug-rendering failures expose stable domain messages without chained configured paths or backend exception details.
- A detection failure followed by a camera cleanup failure produces the distinct `detection_cleanup_failed` status.
- Structured completion output exposes only a face count.
- Boxes, landmarks, frames, model paths, and backend details are not logged.
- Debug output is never automatic and reuses owner-only/no-follow frame persistence.
- No face, person, biometric dataset, embedding, profile, or model artifact is committed.

## Independent Review

The initial independent review blocked M2 on a checksum check/load race, ignored native detector failure status, accepted complex-valued output, frame-intersection validation after confidence filtering, and stale evidence counts. The first re-review approved specification compliance but the security review found chained sensitive exception details, discarded detection-cleanup failures, and unbounded native output cardinality. Every logic finding received a focused failing regression and narrow correction.

The final independent security and specification re-review returned **APPROVED** with no blocker, high, or medium findings. It independently reproduced the exception-sanitization, cleanup-status, cardinality, exact-byte model-loading, native-status, complex-row, and frame-intersection boundaries, then passed the complete 87-test and quality matrix under CPython 3.11.15 and 3.12.13.

## Performance Observations

The 87-test suite completed in less than one second on both supported local runtimes. No detector throughput, accuracy, precision, recall, demographic performance, camera FPS, or production resource claim was evaluated. Those require an approved dataset, accepted model artifact, provider matrix, and M5 evaluation report.

## Known Limitations

- M2 contract tests use injected detections rather than biometric images; they verify adapter correctness, not model accuracy.
- No detector artifact is bundled. Real inference requires an explicitly supplied, rights-reviewed, integrity-pinned compatible artifact.
- The one-frame CLI is an operational/debug surface, not the later bounded asynchronous detection worker.
- Detection results are not tracked, persisted, enrolled, recognized, or connected to settings.
- The repository's own distribution license has not been selected.

## Failures or Skipped Tests

- Physical camera testing was intentionally skipped; M2 uses the M1 deterministic frame sources.
- Real one/multiple-face model-accuracy testing was intentionally deferred because no approved biometric dataset or M5 model acceptance exists.
- An initial compatibility command omitted `--python` on `uv run`, so the repository's Python pin restored 3.11.15 before checks. The exact CPython 3.12.13 matrix was then rerun with `uv run --python 3.12.13` and passed before restoring 3.11.15.
