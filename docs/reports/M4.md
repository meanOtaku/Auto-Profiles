# M4 Implementation Report — Quality Filtering and Alignment

- Milestone: M4 — Quality and Alignment
- Date: 2026-08-01
- Status: **Implementation drafted; verification deferred by owner**

## Scope delivered

- `HeuristicQualityEvaluator` implementing size, sharpness (Laplacian variance), exposure (mean brightness and highlight-clipping fraction), pose (eye-line roll and nose-symmetry yaw), and an occlusion-proxy check (landmark ordering, eye-distance plausibility, landmark-to-box margin).
- Every rejection records one reason string per failing check; a sample can fail more than one check simultaneously, and every failure is reported rather than only the first.
- `SimilarityFaceAligner`, warping accepted crops to the published InsightFace/ArcFace 112x112 five-point reference template at a configurable output size, ready for the M5 embedding adapter.
- `BestSampleTracker`, an in-memory, bounded, per-track retention of the single highest-scoring **accepted** crop, with no disk persistence and explicit `discard()` on track end.
- Strict, disabled-by-default `QualityConfig` with conservative documented starting thresholds, and `create_quality_evaluator()` / `create_aligner()` factories that return `None` unless explicitly enabled, matching the M1–M3 pattern.

## Explicit exclusions

M4 does **not** add embedding generation, similarity comparison, recognition decisions, candidate enrollment, profile persistence, liveness/spoof classification, APIs, or settings changes. The occlusion check is a documented geometric heuristic, not a trained occlusion or anti-spoof model; that gap is closed in M14.

## Configuration

`quality` is disabled by default and bounds:

- `min_face_width`, `min_face_height`
- `min_sharpness_variance`
- `min_mean_brightness`, `max_mean_brightness`, `max_overexposed_fraction`
- `max_roll_degrees`, `max_yaw_asymmetry`
- `max_landmark_margin_violation`
- `aligned_output_width`, `aligned_output_height`
- `best_sample_max_tracks`

All values are conservative starting points and require local dataset evaluation before production use, consistent with CODING_STANDARDS.md §11.

## Verification status and limitations

No test counts, passing quality gates, or production-readiness claims are made. The heuristic thresholds are unevaluated defaults, not locally validated production values. The occlusion and pose checks are geometric proxies and will misclassify real occlusion, extreme yaw, and adversarial presentations; this is a known limitation carried forward to M14. `BestSampleTracker` has not been exercised against a real M3 tracker lifecycle (track expiry calling `discard()`), only in isolation.
