# M5 Implementation Report — Embeddings and Similarity

- Milestone: M5 — Embeddings and Evaluation
- Date: 2026-08-01
- Status: **Implementation drafted; verification deferred by owner**

## Scope delivered

- `FaceEmbedding` value object carrying model name, version, checksum, dimension, and dtype alongside the normalized vector.
- `normalize()` (L2, degenerate-vector rejection) and `cosine_similarity()` (rejects cross-model/cross-dimension comparisons).
- `MockEmbeddingGenerator`: deterministic, content-hash-seeded, normalized vectors requiring no model or biometric data.
- `OnnxEmbeddingGenerator`: OpenCV-DNN-backed ONNX inference behind the same SHA-256 exact-byte integrity gate M2 established for its detector model, avoiding a new `onnxruntime` dependency.
- `threshold_evaluation.py`: `PairScore`, per-threshold `ThresholdMetrics` (FAR/FRR), `ScoreStatistics` (mean/std/min/max/95% CI), and an interpolated equal-error-rate estimate, operating only on caller-supplied labeled pairs.
- `EmbeddingConfig`, disabled and mock-backed by default, carrying `similarity_threshold`/`similarity_margin` as the milestone's configurable initial values.
- CLI `compare` (full detect→quality→align→embed pipeline, prints cosine similarity) and `evaluate-threshold` (reads a caller-supplied JSON pair file, prints the full evaluation report).

## Explicit exclusions

M5 does **not** add the M7 recognition-decision state machine (KNOWN/AMBIGUOUS/UNKNOWN, temporal confirmation, per-track recognition cache), profile persistence, candidate enrollment, liveness, APIs, or settings changes. No embedding model artifact is downloaded, bundled, or selected as a production default; ADR 0002's provenance/license/rights gate remains open for a specific ArcFace-compatible artifact.

## Configuration

`embedding` is disabled by default and bounds:

- `backend` (`mock` | `onnx`), `model_path`, `model_sha256`
- `model_name`, `model_version`, `dimension`, `input_width`, `input_height`
- `similarity_threshold`, `similarity_margin`

All threshold/margin values are unevaluated conservative defaults, not locally validated production values.

## Commands executed

- `ruff format` and `ruff check .`: passed.
- `mypy src tests`: passed with no issues in 28 source files.
- Ad hoc, non-persisted interpreter smoke checks (not pytest, not committed as tests): `MockEmbeddingGenerator` determinism (identical content → identical vector, similarity 1.0; differing content → low similarity), unit-norm verification, cross-model comparison rejection, a synthetic six-pair `evaluate_thresholds()` sweep with FAR/FRR/EER/statistics/cohort output, and end-to-end CLI smoke tests of both `compare` (mock pipeline, correctly fails closed with `no_face_detected` since the mock detector factory returns no configured detections) and `evaluate-threshold` (JSON pairs file, full report printed).
- Automated `pytest` and the full quality/packaging matrix were **not run**, per the owner's explicit request to defer tests for now.

## Verification status and limitations

No test counts, passing quality gates, or production-readiness claims are made. No real accuracy evidence exists: there is no approved, privacy-safe biometric evaluation dataset and no rights-reviewed embedding model artifact in this environment, so "same-person and different-person test sets are evaluated" and "local dataset report exists" (HERMES/ROADMAP M5 exit criteria) are **not** satisfied — this is an explicit, honestly recorded gap, not a claimed pass. `similarity_threshold`/`similarity_margin` are placeholder defaults pending that evaluation. The `OnnxEmbeddingGenerator` backend has not been exercised against any real ONNX model in this session; only its integrity-gate and error-translation logic follow the same pattern already used (and locally smoke-tested) by M2's YuNet backend.
