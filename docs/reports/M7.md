# M7 Implementation Report — Known-Person Recognition

- Milestone: M7 — Known-Person Recognition
- Date: 2026-08-01
- Status: **Implementation drafted; verification deferred by owner**

## Scope delivered

- `decision.py`: `RecognitionState`, `ProfileMatch`, `RecognitionDecision`, and `decide()` implementing the threshold/margin rule from ARCHITECTURE.md section 8.
- `matcher.py`: `find_nearest_profiles()`, per-profile best-similarity ranking over caller-supplied embeddings, no I/O.
- `cache.py`: `RecognitionCache`, bounded per-track temporal confirmation with sticky confirmed state (flicker resistance) and explicit `discard()` on track end.
- `recognizer.py`: `KnownPersonRecognizer`, the only M7 component that reads M6's `ProfileRepository` (active profiles only).
- `RecognitionConfig` (disabled by default) and `create_recognizer()`, which also requires `embedding.enabled` since it consumes M5's `similarity_threshold`/`similarity_margin`.
- CLI `recognize --image PATH [--track-id N]`.

## Explicit exclusions

M7 does **not** add candidate enrollment/deduplication (M8), active-user selection across tracks/profiles (M10), settings application, or a network API. Quality and liveness rejection remain owned by M4 and M14; this module has no corresponding states.

## Configuration

`recognition` is disabled by default and bounds `min_consistent_observations`, `confirmation_window_seconds`, and `max_tracks`. It reuses `embedding.similarity_threshold`/`similarity_margin` from M5 rather than duplicating threshold configuration.

## Verification status and limitations

No test counts, passing quality gates, or production-readiness claims are made. `KnownPersonRecognizer` decrypts every active profile's every embedding on every `recognize()` call — a known, explicitly documented O(profiles × embeddings) performance limitation deferred to M15. `RecognitionCache`'s sticky-confirmation behavior has only been exercised with a handful of hand-constructed scenarios, not a systematic scenario suite (crossing tracks, long occlusion gaps, rapid candidate switching). `min_consistent_observations`/`confirmation_window_seconds` defaults are unevaluated starting points, same caveat as M5's threshold/margin.
